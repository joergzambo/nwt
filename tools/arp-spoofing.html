ARP-Spoofing: sich zwischen zwei Geräte schieben

Beim ARP-Spoofing (auch ARP-Poisoning) schickt der Angreifer gefälschte ARP-Antworten ins Netz: „Die IP des Gateways gehört zu meiner MAC-Adresse.“ Opfer und Gateway tragen die falsche Zuordnung in ihren ARP-Cache ein und schicken ihren Verkehr fortan an den Angreifer – ein Man-in-the-Middle auf Layer 2.

⚠️ Nur im eigenen Labornetz. Diese Anleitung dient dem Unterricht und dem Verständnis der Abwehr. Angriffe auf fremde Netze sind strafbar.

Warum funktioniert der Angriff?

Wozu ARP?

Um ein IP-Paket im LAN zuzustellen, braucht ein Gerät die MAC-Adresse zur Ziel-IP. Es fragt per Broadcast: „Who has 192.168.1.1? Tell 192.168.1.50.“ Der Besitzer antwortet: „192.168.1.1 is at aa:bb:…“. Das Ergebnis landet im ARP-Cache (arp -a).

Die Schwachstellen von ARP

  • Keine Authentifizierung. Jede ARP-Antwort wird geglaubt – egal, wer sie schickt.
  • Zustandslos. Ein Gerät übernimmt eine Antwort auch dann, wenn es nie gefragt hat (unaufgefordertes/„gratuitous“ ARP).
  • Letzte Antwort gewinnt. Der Angreifer schickt seine Fälschung einfach ständig – sie überschreibt den echten Eintrag.
  • Broadcast-Domäne. Jedes Gerät im selben VLAN kann mitspielen.

Wie bei DHCP ist das keine Software-Lücke, sondern ein Protokoll ganz ohne Schutzmechanismen.

Der Angriff Schritt für Schritt

So sieht es im Wireshark aus

Filter arp. Verräterisch sind unaufgeforderte ARP-Replies und vor allem Wiresharks Warnung „duplicate use of … detected“: Eine IP wird plötzlich zwei verschiedenen MAC-Adressen zugeordnet.

Woran man den Angriff erkennt

  • Viele ARP-Replies ohne vorausgehenden Request (unaufgefordert), oft im Sekundentakt wiederholt.
  • Wireshark markiert gelb/schwarz: „duplicate use of 192.168.1.1 detected“ – zwei MACs für eine IP.
  • Am Opfer zeigt arp -a für zwei verschiedene IPs dieselbe MAC (die des Angreifers).
  • Tools wie arpwatch oder XArp melden die geänderte Zuordnung automatisch.

Lab-Anleitung: ARP-Spoofing mit Ettercap (grafisch)

Angreifer-PC (Kali) und Opfer am selben Switch/VLAN, dazu das Gateway. Ettercap vergiftet die ARP-Caches von Opfer und Gateway, der Verkehr läuft danach über den Angreifer – parallel im Wireshark mitlesen.

Ettercap grafisch starten

Als root starten – es öffnet sich die grafische Oberfläche.

sudo ettercap -G

Sniffing starten

Oben als Primary Interface das Interface zum Switch (z. B. eth0) wählen und mit dem Häkchen ✓ (Accept) bestätigen. Ettercap startet das Unified Sniffing.

Hosts suchen

Im Menü (⋮) Hosts ▸ Scan for hosts. Danach Hosts ▸ Hosts list öffnet die Liste aller gefundenen Geräte mit IP und MAC.

Ziele festlegen

In der Hosts-Liste das Gateway markieren und Add to Target 1, dann das Opfer markieren und Add to Target 2. (Ohne Ziele vergiftet Ettercap das ganze Netz – im Lab lieber gezielt.)

ARP-Poisoning starten

Im MITM-Menü (🌐 / Zielscheibe) ARP poisoning… wählen, „Sniff remote connections“ anhaken und mit OK starten. Ettercap schickt nun beiden Zielen gefälschte ARP-Replies.

Als Einzeiler im Terminal:
sudo ettercap -T -i eth0 -M arp:remote /192.168.1.1// /192.168.1.50//
(-T Textmodus, -M arp:remote = ARP-Poisoning beider Richtungen, dann Gateway und Opfer.)

Mitlesen

Ettercap zeigt erkannte Zugangsdaten unter View ▸ Connections. Für den vollen Verkehr parallel Wireshark auf eth0 laufen lassen. Am Opfer prüfen: arp -a zeigt fürs Gateway nun die Angreifer-MAC.

Sauber beenden

MITM ▸ Stop MITM attack(s). Wichtig: Ettercap schickt jetzt die echten ARP-Einträge nach (Re-ARP), damit Opfer und Gateway wieder sauber kommunizieren. Erst danach schließen.

Schutz: Dynamic ARP Inspection und mehr

Cisco: Dynamic ARP Inspection (DAI)

DAI prüft jedes ARP-Paket an nicht vertrauten Ports gegen die DHCP-Snooping-Bindungstabelle (IP ↔ MAC ↔ Port). Passt die Zuordnung nicht, wird das ARP-Paket verworfen. Der Angreifer kann keine fremde IP mehr beanspruchen.

Switch(config)# ip dhcp snooping
Switch(config)# ip dhcp snooping vlan 10
Switch(config)# ip arp inspection vlan 10
!
Switch(config)# interface Gi0/24          ! Uplink zu Gateway/Server
Switch(config-if)#  ip dhcp snooping trust
Switch(config-if)#  ip arp inspection trust
!
Switch# show ip arp inspection vlan 10

DAI setzt DHCP Snooping voraus – ohne die Bindungstabelle weiß der Switch nicht, welche MAC zu welcher IP gehört. Für fest vergebene IPs ohne DHCP nimmt man eine ARP-ACL. Verschärfen: ip arp inspection validate src-mac dst-mac ip.

Weitere Maßnahmen

  • Statische ARP-Einträge für kritische Ziele (z. B. das Gateway): arp -s 192.168.1.1 aa-bb-cc-dd-ee-ff – überschreibbar nur manuell.
  • Erkennung am Host: arpwatch, XArp melden geänderte IP↔MAC-Zuordnungen.
  • Verschlüsselung (HTTPS, VPN, SSH) begrenzt den Schaden: Der Angreifer sieht zwar den Verkehr, aber nur verschlüsselt.
  • Port-Security und Private VLANs erschweren, dass ein Gerät überhaupt frei funkt.
