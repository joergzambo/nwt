NTP, Syslog und SNMP

Drei Dienste halten ein Netz im Griff: NTP sorgt für gleiche Uhrzeit, Syslog sammelt Meldungen zentral, SNMP überwacht und meldet Zustände. Ohne synchrone Zeit sind Logs wertlos – deshalb gehören sie zusammen.

NTP – die Zeit

Alle Geräte brauchen die gleiche Uhrzeit – sonst passen Log-Zeitstempel nicht zusammen, Zertifikate und zeitbasierte Authentifizierung schlagen fehl. NTP (UDP 123) synchronisiert hierarchisch über Stratum-Ebenen:

  • Stratum 0 – die Referenzuhr (Atomuhr, GPS). Stratum 1 – direkt daran angeschlossen. Jede weitere Ebene zählt hoch (je höher, desto weiter weg).
  • Ein Gerät kann selbst Zeitquelle sein und seine Zeit an andere weitergeben.
Router(config)# ntp server 192.168.1.1
Router(config)# ntp update-calendar
Router# show ntp status        ! synchronisiert? welches Stratum?
Router# show ntp associations

Syslog – die Meldungen

Geräte schicken Ereignisse an einen Syslog-Server (UDP 514). Jede Meldung hat eine Severity 0–7 – je kleiner die Zahl, desto dringender:

StufeNameBedeutung
0EmergencySystem unbrauchbar
1Alertsofortiges Handeln nötig
2Criticalkritischer Zustand
3ErrorFehlermeldung
4WarningWarnung
5Notificationnormal, aber bemerkenswert (z. B. Interface up/down)
6Informationalreine Info
7DebuggingDebug-Ausgaben

SNMP – die Überwachung

SNMP (UDP 161) überwacht Geräte. Ein Manager (NMS) fragt die Agents auf den Geräten ab; Werte stehen in der MIB, adressiert über OIDs.

  • Polling (GET) – der Manager fragt aktiv Werte ab.
  • Trap – der Agent meldet von sich aus ein Ereignis (UDP 162), ohne gefragt zu werden.
  • Versionen: v1/v2c nutzen Community-Strings (Klartext!), v3 bietet Authentifizierung und Verschlüsselung.
  • Community: read-only (RO) oder read-write (RW).
Router(config)# snmp-server community NWTro ro
Router(config)# snmp-server host 192.168.1.10 version 2c NWTro
Router(config)# snmp-server enable traps
v1/v2c schicken den Community-String im Klartext – im produktiven Netz SNMPv3 verwenden.
