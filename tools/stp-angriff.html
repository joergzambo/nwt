Angriff auf die Root Bridge

Spanning Tree wählt die Root Bridge allein über die kleinste Bridge-ID (Priorität + MAC). Wer gefälschte BPDUs mit Priorität 0 einspeist, wird selbst Root – und lenkt den Datenverkehr über sich (Man-in-the-Middle) oder stört das ganze Netz. Schutz geben BPDU Guard und Root Guard.

Wie der Angriff funktioniert

Normalerweise hat der zentrale Switch die niedrigste Priorität und ist Root. Der Angreifer schließt einen Laptop an einen ganz normalen Port an und sendet überlegene BPDUs mit Priorität 0. Da 0 kleiner ist als jede normale Priorität (Standard 32768, getunt z. B. 4096), gewinnt der Angreifer die Root-Wahl.

Folge: Spanning Tree rechnet die Topologie neu, die Wege führen nun über den Angreifer. Er kann mitlesen (MITM) oder durch ständige Neuwahlen das Netz lahmlegen (DoS).

Mit Yersinia

Das Tool Yersinia beherrscht STP-Angriffe out of the box – u. a. „Claiming Root Role" und „Claiming Other Role". Es sendet fortlaufend überlegene BPDUs.

Schutzmaßnahmen

BPDU Guard – an Access-Ports

An PortFast-/Access-Ports dürfen gar keine BPDUs ankommen. Kommt doch eine (z. B. vom Angreifer-Laptop), wird der Port sofort err-disabled abgeschaltet.

interface range Fa0/1 - 24
 switchport mode access
 spanning-tree portfast
 spanning-tree bpduguard enable
! oder global:
spanning-tree portfast bpduguard default

Root Guard – an Switch-Ports

Auf Ports, über die nie die Root Bridge erreichbar sein soll, ignoriert Root Guard überlegene BPDUs und setzt den Port in den Zustand root-inconsistent (blockiert), bis die BPDUs aufhören.

interface Gi0/1
 spanning-tree guard root
Faustregel: BPDU Guard auf Endgeräte-Ports (PortFast), Root Guard auf Uplinks zu Switches, bei denen kein Root sitzen darf. Zusätzlich hilft Root Guard gegen versehentlich falsch konfigurierte Switches.
