Rogue-DHCP-Server: das falsche Gateway unterschieben

Ein Rogue-DHCP-Server ist ein nicht autorisierter DHCP-Server im Netz. Er beantwortet die Anfragen der Clients mit seinen eigenen Werten – vor allem mit einem falschen Standardgateway und DNS-Server. Dann läuft der gesamte Internet-Verkehr der Opfer über den Angreifer: ein Man-in-the-Middle. Oft ist es aber auch nur ein versehentlich eingesteckter Heimrouter.

⚠️ Nur im eigenen Labornetz. Diese Anleitung dient dem Unterricht und dem Verständnis der Abwehr. Angriffe auf fremde Netze sind strafbar.

Warum funktioniert der Angriff?

Der erste Offer gewinnt

Ein Client schickt sein Discover als Broadcast an alle. Jeder DHCP-Server im selben Netz hört es und darf antworten. Der Client nimmt den zuerst eintreffenden Offer – welcher Server das ist, prüft er nicht.

Ein Rogue-Server, der näher am Client sitzt oder schneller antwortet, gewinnt dieses Rennen. Nach einer DHCP-Starvation ist der echte Pool leer – dann antwortet sowieso nur noch der Rogue.

Die Schwachstellen

  • Keine Authentifizierung. Der Client kann einen echten nicht von einem gefälschten Server unterscheiden.
  • Wettlauf (Race Condition). Es zählt nur, wer zuerst antwortet.
  • Gateway und DNS kommen vom Server. Wer sie setzt, lenkt den Verkehr – ideal für Man-in-the-Middle.
  • Oft gar kein Angriff. Ein mitgebrachter WLAN-Router mit aktivem DHCP verteilt im Firmennetz munter falsche Adressen.

Der Angriff Schritt für Schritt

So sieht es im Wireshark aus

Über einen SPAN-Port läuft der Verkehr des Client-Ports auf den Mitschnitt-PC. Das verräterische Zeichen: zwei Offer auf ein Discover – mit verschiedenen Gateways und von verschiedenen Server-MACs.

bootp  (bzw. dhcp)
No.TimeSource (MAC)Dest.Prot.Info

Woran man den Rogue erkennt

  • Zwei DHCP Offer auf ein Discover – mit unterschiedlichem Gateway (Option 3) und DNS (Option 6).
  • Der Offer kommt von einer unerwarteten Server-IP/MAC (nicht die des echten Servers).
  • Filter in Wireshark: dhcp.option.dhcp == 2 zeigt nur die Offer; die Server-Identifier (Option 54) vergleichen.
  • Am Client: ipconfig /all zeigt plötzlich ein falsches Standardgateway oder einen falschen DHCP-Server.

Lab-Anleitung: Rogue-Server mit Yersinia

Derselbe Aufbau wie bei der Starvation: Angreifer-PC (Kali) und Opfer am Cisco-Switch, Mitschnitt-PC am SPAN-Zielport. Oft kombiniert man beides – erst Starvation, dann Rogue, damit nur noch der Rogue antwortet.

Yersinia interaktiv starten

Als root im Terminal starten.

sudo yersinia -I

Interface und Protokoll wählen

Taste i → Interface (z. B. eth0) aktivieren, q zurück. Dann g → Protokoll DHCP wählen.

Rogue-Server starten

Taste x öffnet das Angriffsfenster. „creating DHCP rogue server“ wählen und mit Enter starten. Yersinia antwortet nun auf Discover mit sich selbst als Gateway/DNS.

Als Einzeiler: sudo yersinia dhcp -attack 2 -interface eth0 (Attack 2 = Rogue-Server). Realistischer ist ein echter DHCP-Server, z. B. dnsmasq mit eigener dhcp-range und dhcp-option=3,<Angreifer-IP>.

Opfer eine Adresse holen lassen

C:\> ipconfig /release
C:\> ipconfig /renew
C:\> ipconfig /all          ! Default Gateway = Angreifer-IP?

Man-in-the-Middle scharf schalten

Damit das Opfer trotzdem ins Internet kommt (und nichts merkt), muss der Angreifer weiterleiten und mitlesen:

sudo sysctl -w net.ipv4.ip_forward=1     ! Pakete weiterreichen
# Verkehr in Wireshark mitschneiden, Zugangsdaten in HTTP/DNS mitlesen

Angriff stoppen

In Yersinia L → Angriff beenden, q schließen. Am Switch/Server die falschen Leases prüfen und löschen.

Schutz auf Cisco: DHCP Snooping

DHCP Snooping teilt die Ports in vertraut und nicht vertraut. Nur vertraute Ports (zum echten Server/Uplink) dürfen Server-Nachrichten (Offer, ACK, NAK) senden. Ein Rogue an einem nicht vertrauten Port wird sofort verworfen.

Switch(config)# ip dhcp snooping
Switch(config)# ip dhcp snooping vlan 10
!
Switch(config)# interface Gi0/24                 ! Uplink zum echten DHCP-Server
Switch(config-if)# ip dhcp snooping trust
!
Switch(config)# interface range Gi0/1 - 23       ! alle Client-Ports
Switch(config-if-range)# ip dhcp snooping limit rate 15   ! optional gegen Starvation
!
Switch# show ip dhcp snooping                     ! trusted/untrusted je Port
Switch# show ip dhcp snooping binding             ! MAC ↔ IP ↔ Port ↔ VLAN

Standardmäßig sind alle Ports untrusted – man muss nur den Server-Port auf trust setzen. Verwirft der Switch ein Rogue-Offer, zählt show ip dhcp snooping die Drops. Ergänzend: Port-Security gegen die MAC-Flut (siehe DHCP-Starvation).

Schutz auf UniFi

UniFi (UDM/USW) bringt zwei Mechanismen mit: eine Erkennung fremder DHCP-Server und ein DHCP Guarding, das Antworten fremder Server blockt.

DHCP Guarding (blockt den Rogue)

  1. UniFi Network öffnen: Settings ▸ Networks
  2. Das betroffene Netz (VLAN) wählen, dann Advanced ▸ DHCP Guarding einschalten.
  3. Die IP-Adresse(n) des echten DHCP-Servers als „Trusted DHCP Server“ eintragen.
  4. Die UniFi-Geräte verwerfen nun DHCP-Server-Antworten (Offer/ACK) von jeder anderen Quelle – der Rogue kommt beim Client nicht mehr an.

Das ist das UniFi-Gegenstück zu „trust“ bei Cisco: Statt eines vertrauten Ports definiert man die vertraute Server-IP.

Rogue-DHCP-Erkennung (alarmiert)

  1. Unter Settings ▸ System bzw. in den Alerts/Insights meldet UniFi, wenn im Netz DHCP-Offer von einem unbekannten Server auftauchen.
  2. Die Meldung nennt die IP/MAC des fremden Servers und den Switch-Port – so findet man den eingesteckten Heimrouter schnell.

Erkennung allein blockt nicht – sie warnt nur. Zum Blocken braucht es DHCP Guarding.
