Static NAT: Server aus dem Internet erreichbar machen

Bei PAT entsteht ein Eintrag in der NAT-Tabelle erst, wenn ein Gerät von innen eine Verbindung aufbaut. Ein Webserver im eigenen Netz wäre so von außen nie erreichbar. Static NAT löst das: ein fester Eintrag, der immer in der Tabelle steht – auch für Verbindungen, die von außen kommen.

Die Idee: ein fester Eintrag

Static NAT (1:1)

Eine öffentliche Adresse wird fest einer privaten zugeordnet – in beide Richtungen, für alle Ports.

203.0.113.10 ↔ 192.168.10.50

Braucht eine eigene öffentliche Adresse pro Server. Der Server ist damit unter dieser Adresse komplett erreichbar – was offen sein darf, muss eine Firewall-Regel oder ACL festlegen.

Portweiterleitung (statisches PAT)

Nur ein Port einer öffentlichen Adresse wird fest auf einen Port eines Servers gelegt. Der Port darf sich dabei ändern.

203.0.113.5:8080 ↔ 192.168.10.50:80

Kommt mit einer einzigen öffentlichen Adresse aus – der des Routers. Über verschiedene Ports lassen sich mehrere Server dahinter erreichen. Das ist die „Portweiterleitung“ der Heimrouter.

Schritt für Schritt: ein Zugriff von außen

Wähle die Variante. Der Eintrag steht von Anfang an in der Tabelle – er wurde konfiguriert, nicht gelernt.

Inside Local (Server privat)Inside Global (Server öffentlich)Outside (Client im Internet)

Der Unterschied zu PAT

  • PAT: Eintrag entsteht von selbst, wenn innen jemand hinaus will – und verfällt wieder. Von außen kommt niemand herein.
  • Static NAT: Eintrag ist konfiguriert und bleibt. Von außen kommend wird die Ziel-Adresse getauscht, auf dem Rückweg die Quell-Adresse – genau umgekehrt wie bei PAT.

Cisco-Konfiguration

Einrichten

! Static NAT 1:1  (innen  →  außen)
R1(config)# ip nat inside source static 192.168.10.50 203.0.113.10
!
! Portweiterleitung: außen Port 8080 → Server Port 80
R1(config)# ip nat inside source static tcp 192.168.10.50 80 203.0.113.5 8080
!
! Innen und außen festlegen – wie bei PAT
R1(config)# interface Gi0/0
R1(config-if)#  ip nat inside
R1(config)# interface Gi0/1
R1(config-if)#  ip nat outside

Reihenfolge merken: zuerst die private (Inside Local), dann die öffentliche Adresse (Inside Global). Bei der Portweiterleitung steht der Port jeweils direkt hinter seiner Adresse.

Kontrollieren

R1# show ip nat translations
Pro Inside global      Inside local       Outside local  Outside global
--- 203.0.113.10       192.168.10.50      ---            ---
tcp 203.0.113.5:8080   192.168.10.50:80   ---            ---

Statische Einträge stehen sofort und dauerhaft in der Tabelle – auch ohne Verkehr. Die Outside-Spalten bleiben leer (---), weil der Eintrag für jeden Partner im Internet gilt. Beim 1:1-Eintrag steht auch bei „Pro“ nur ---: Er gilt für alle Protokolle und Ports.

„Portweiterleitung“ am Heimrouter vs. Weiterleiten auf einer Firewall

Technisch passiert in beiden Fällen dasselbe: Die Ziel-Adresse wird getauscht. Der Unterschied liegt darin, was rundherum geschieht.

Portweiterleitung (SOHO-Router)Firewall im Unternehmen

Merke: NAT ist keine Sicherheitsfunktion. Die Übersetzung sagt nur, wohin ein Paket geht. Ob es darf, entscheidet die Firewall-Regel. Der Heimrouter versteckt diese zweite Entscheidung – die Firewall macht sie sichtbar. Hinter CGNAT funktioniert übrigens keine der beiden Varianten.

Proxy ARP: wer antwortet für die zusätzliche Adresse?

Beim 1:1-NAT verwendet man oft eine öffentliche Adresse, die kein Gerät wirklich hat – im Beispiel 203.0.113.10. Der Router selbst hat außen 203.0.113.5.

Der Router des Providers will das Paket für 203.0.113.10 zustellen. Die Adresse liegt in seinem eigenen Netz, also fragt er per ARP: „Who has 203.0.113.10?“ Kein Gerät besitzt diese Adresse – eigentlich bliebe die Frage unbeantwortet. Deshalb antwortet R1 stellvertretend mit seiner eigenen MAC-Adresse. Das nennt man Proxy ARP. Erst dadurch landen die Pakete bei R1, der sie dann übersetzt.

Wann braucht man es?

  • Ja: Die NAT-Adresse liegt im selben Netz wie das Outside-Interface, ist aber nicht dessen eigene Adresse.
  • Nein: Portweiterleitung auf die eigene Interface-Adresse – auf die antwortet der Router ohnehin.
  • Nein: Der Provider routet ein zusätzliches Netz zum Router. Dann wird gar nicht per ARP gefragt.

In der Praxis

  • Cisco IOS beantwortet ARP-Anfragen für statische NAT-Adressen automatisch.
  • Auf manchen Firewalls muss man Proxy ARP für die NAT-Adresse eigens einschalten oder eintragen.
  • Typischer Fehler: NAT-Regel und Firewall-Regel stimmen, trotzdem kommt kein einziges Paket an – weil niemand auf die ARP-Anfrage antwortet. Kontrolle: im Mitschnitt nach unbeantworteten ARP-Requests suchen.
