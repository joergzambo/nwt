Die CLI-Modi

Die Cisco-Kommandozeile ist in Modi gegliedert. Der Prompt zeigt immer, wo du gerade bist. Klick dich durch:

ModusPromptHinein mitWofür
User-EXECRouter>(Login)Nur anschauen: ping, einige show. Nichts ändern.
Privileged-EXECRouter#enableAlle show/debug, reload, copy. „Admin-Modus".
Global-ConfigRouter(config)#configure terminalGeräteweite Einstellungen (Hostname, Benutzer …).
Interface-ConfigRouter(config-if)#interface Gi0/0Ein Interface konfigurieren (IP, Beschreibung …).
Line-ConfigRouter(config-line)#line vty 0 4Konsole/VTY: Passwort, Timeout, Transport.
Router-ConfigRouter(config-router)#router ospf 1Routing-Protokoll einstellen.
exit = eine Ebene zurück · end oder Strg+Z = direkt zurück zum Privileged-EXEC · disable = zurück zum User-EXEC. Mit do <befehl> kannst du aus dem Config-Modus einen Privileged-Befehl ausführen (z. B. do show ip int brief).

Tastenkürzel (PuTTY / IOS)

Diese Kürzel funktionieren direkt in der IOS-Zeile (auch über PuTTY). Sie sparen enorm Zeit beim Tippen langer Befehle:

KürzelWirkung
Strg+AAn den Anfang der Zeile springen
Strg+EAn das Ende der Zeile springen
Strg+DZeichen unter dem Cursor löschen
Strg+WEin Wort links löschen
Strg+UDie ganze Zeile löschen
Strg+KVom Cursor bis Zeilenende löschen
Strg+RZeile neu anzeigen (nach einer Logmeldung)
Strg+CBefehl/Konfiguration abbrechen
Strg+ZConfig beenden → zurück zum Privileged-EXEC
Strg+Umschalt+6Break: laufenden Vorgang abbrechen (z. B. hängender ping/traceroute oder DNS-Lookup)
TabBefehl vervollständigen
?Hilfe: zeigt mögliche Befehle/Optionen
Pfeil ↑ / Strg+PVorherigen Befehl aus dem Verlauf

Die Speicher eines Cisco-Geräts

Ein Cisco-Gerät hat vier wichtige Speicher. Entscheidend ist: Was überlebt einen Neustart – und was nicht?

SpeicherInhaltNach Neustart?Vergleich PC
RAMrunning-config (aktive Konfiguration), Routing-Tabelle, ARP-Cache, Paketpuffer. Das IOS läuft hier.weg (flüchtig)Arbeitsspeicher
ROMBootstrap, POST (Selbsttest), ROMMON (Notfall-Modus). Fest eingebaut.bleibtBIOS
NVRAMstartup-config (gespeicherte Konfiguration), Configuration Register.bleibtkleiner Dauerspeicher
FlashIOS-Image (das Betriebssystem), oft Backup-Configs.bleibtFestplatte/SSD

Beim Start lädt das Gerät das IOS aus dem Flash in den RAM und dann die startup-config aus dem NVRAM in den RAM (→ wird zur running-config).

Router# copy running-config startup-config    ! Änderungen sichern (RAM → NVRAM), kurz: write memory
Router# show running-config                   ! aktive Konfiguration (RAM)
Router# show startup-config                   ! gespeicherte Konfiguration (NVRAM)
Router# show flash:                           ! IOS-Image(s) im Flash
Router# show version                          ! IOS-Version, Uptime, Config-Register
Merke: Wer nur konfiguriert und nicht copy run start macht, verliert alles beim nächsten Stromausfall – die running-config liegt nur im flüchtigen RAM.
