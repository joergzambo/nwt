Extended-Access-Listen

Eine Standard-ACL kennt nur die Quelle. Eine Extended-ACL prüft viel genauer: Protokoll, Quelle, Ziel und bei TCP/UDP den Port – also welcher Dienst gemeint ist. Damit lässt sich zum Beispiel sagen: „Das Schülernetz darf auf den Webserver, aber nicht per Telnet.“

Aufbau einer Zeile

TeilBedeutungBeispiele
Nummer100–199 oder 2000–2699 = Extended110
Aktionerlauben oder verwerfenpermit · deny
Protokollip = alles · tcp · udp · icmptcp
QuelleAdresse + Wildcard, host oder any192.168.10.0 0.0.0.255
Zielgenausohost 10.1.1.10
Port (optional)nur bei tcp/udp, meist der Ziel-Porteq 80 · gt 1023 · range 20 21
Zusätzeestablished, log, bei ICMP der Typecho · log

Wichtig: Die Port-Angabe steht hinter dem Ziel – dann meint sie den Ziel-Port (den Dienst). Steht sie hinter der Quelle, prüft sie den Quell-Port. Ohne Port-Angabe gilt die Zeile für alle Ports. Wildcards, host und any funktionieren wie bei der Standard-ACL.

Operatoren und Zusätze

eq 80gleich 80
neq 23ungleich 23
lt 1024kleiner als 1024
gt 1023größer als 1023
range 20 21von 20 bis 21
establishednur TCP-Pakete einer schon bestehenden Verbindung (ACK- oder RST-Bit gesetzt) – praktisch für Antworten von außen
logTreffer werden protokolliert
icmp … echoPing-Anfrage (echo-reply = Antwort)

ip umfasst alle Protokolle. Eine Zeile deny ip … sperrt also auch TCP, UDP und Ping. UDP kennt kein established – es hat keine Verbindungen.

Konfiguration



 
Nummerierte Extended-ACL
R1(config)# access-list 110 permit tcp 192.168.10.0 0.0.0.255 host 10.1.1.10 eq 80
R1(config)# access-list 110 permit tcp 192.168.10.0 0.0.0.255 host 10.1.1.10 eq 443
R1(config)# access-list 110 deny   icmp any host 10.1.1.10 echo
R1(config)# access-list 110 permit ip any any
!
! nahe an der Quelle, Richtung in
R1(config)# interface Gi0/1
R1(config-if)#  ip access-group 110 in

 
Named Extended-ACL mit Sequenznummern
R1(config)# ip access-list extended SCHUELER-IN
R1(config-ext-nacl)#  10 permit tcp 192.168.10.0 0.0.0.255 host 10.1.1.10 eq www
R1(config-ext-nacl)#  20 deny   tcp 192.168.10.0 0.0.0.255 any eq telnet log
R1(config-ext-nacl)#  30 permit ip any any
R1(config-ext-nacl)#  25 deny udp any any eq tftp      ! zwischen 20 und 30 eingefügt
R1(config-ext-nacl)#  no 20                            ! Zeile 20 gelöscht
R1(config)# interface Gi0/1
R1(config-if)#  ip access-group SCHUELER-IN in

R1# show access-lists SCHUELER-IN
R1# show ip interface Gi0/1

  
Auf aktuellen IOS-Versionen kann man auch eine nummerierte ACL mit ip access-list extended 110 öffnen und Zeilen über Sequenznummern einfügen oder löschen. Sicher ist trotzdem: ACL im Editor schreiben und dann einfügen.





Beispiel: Webserver in der DMZ



 
R1(config)# access-list 120 permit tcp any host 172.16.1.80 eq 80
R1(config)# access-list 120 permit tcp any host 172.16.1.80 eq 443
R1(config)# access-list 120 deny   ip any any log
R1(config)# interface Gi0/0                    ! Richtung Internet
R1(config-if)#  ip access-group 120 in

 
Aus dem Internet ist nur der Webserver erreichbar – und nur auf Port 80 und 443. Alles andere wird verworfen und protokolliert. Für den Rückweg der Verbindungen, die von innen aufgebaut werden, bräuchte man zusätzlich z. B. permit tcp any 192.168.10.0 0.0.0.255 established oder gleich eine Firewall.



Platzierung: so nahe an der Quelle wie möglich


Eine Extended-ACL kennt Quelle und Ziel. Sie kann also gefahrlos nahe an der Quelle stehen: am Router des Quell-Netzes, auf dem Interface, an dem die Pakete hereinkommen, inbound. Unerwünschter Verkehr wird so gleich verworfen und belastet keine Leitungen. Probiere es im Netzplan aus deinem Arbeitsblatt aus:
