RIP-Authentifizierung

RIP verteilt seine Routen ungeprüft: Wer gefälschte Routing-Updates einspeist, kann den Verkehr umlenken (Man-in-the-Middle) oder ins Leere schicken (Blackhole). Mit Authentifizierung – am besten MD5 über eine key-chain – nimmt ein Router nur noch Updates von Nachbarn an, die den richtigen Schlüssel kennen.

Wie der Angriff funktioniert

Ohne Authentifizierung glaubt ein RIP-Router jedem, der RIPv2-Updates an die Multicast-Adresse 224.0.0.9 schickt. Ein Angreifer bewirbt z. B. eine bessere Metrik für ein Zielnetz oder eine eigene Default-Route. Der Opfer-Router trägt die gefälschte Route ein – und schickt den Verkehr über den Angreifer.

Gegenmittel: RIP-Authentifizierung. Beide Nachbarn teilen einen Schlüssel (key-chain). Updates ohne gültige Prüfsumme werden verworfen. MD5 überträgt nur einen Hash – Plaintext dagegen sendet das Passwort offen und ist nur ein schwacher Schutz.

Konfiguration

Schlüssel in einer key-chain ablegen, am Interface Modus und key-chain zuweisen – auf beiden Seiten mit gleichem Schlüssel:

key chain RIP-KEYS
 key 1
  key-string Rip#Secret1
!
router rip
 version 2
 network 10.0.0.0
!
interface Gi0/0
 ip rip authentication mode md5                 ! md5 statt text!
 ip rip authentication key-chain RIP-KEYS

MD5 (empfohlen)

Überträgt nur einen Hash des Updates. Das Passwort selbst geht nie über die Leitung.

Plaintext (text)

Das Passwort wird im Klartext mitgeschickt – ein Mitschnitt zeigt es sofort. Nur Notlösung.

Achtung: Stimmen die Schlüssel der beiden Nachbarn nicht überein, entsteht gar keine RIP-Nachbarschaft – die Router tauschen dann keine Routen mehr aus.
