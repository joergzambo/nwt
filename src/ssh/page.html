Sicherer Zugang: SSH, RADIUS und Konsole

Wer ein Netzgerät verwaltet, öffnet ein Einfallstor – darum darf der Zugang nicht über Telnet im Klartext laufen. Hier richten wir SSH ein, sichern Konsole und VTY ab und erweitern das Ganze um eine zentrale Anmeldung per RADIUS (AAA).

Warum Telnet nicht mehr zeitgemäß ist

Telnet überträgt alles im Klartext – auch Benutzername und Passwort. Wer im selben Netz mitschneidet (z. B. mit Wireshark), liest die Zugangsdaten einfach mit. SSH verschlüsselt die gesamte Sitzung.

Telnet-Mitschnitt (Port 23)

Username: admin Password: cisco123 show running-config … alles im Klartext lesbar

SSH-Mitschnitt (Port 22)

a7f3 9c21 be04 11d8 5faa … e2b9 77c4 10af 3d62 c091 … verschlüsselt – nichts lesbar
Weitere Gründe gegen Telnet: keine Integritätssicherung (Daten können manipuliert werden), keine Server-Authentifizierung, von Prüfungen/Standards (z. B. im Firmenumfeld) praktisch verboten. SSH Version 2 ist Pflicht – Version 1 hat bekannte Schwächen.

SSH einrichten (Cisco)

  1. Hostname und Domain setzen – beides geht in den RSA-Schlüssel ein.
    hostname R1 · ip domain-name htl.local
  2. RSA-Schlüssel erzeugen (Länge ≥ 2048 Bit).
    crypto key generate rsa modulus 2048
  3. Lokalen Benutzer anlegen (verschlüsselt).
    username admin secret cisco123
  4. enable secret setzen (nie enable password).
    enable secret cisco123
  5. VTY-Leitungen auf SSH beschränken und lokale Anmeldung verlangen.
    line vty 0 4 · transport input ssh · login local
  6. SSH Version 2 erzwingen.
    ip ssh version 2

Kontrolle: show ip ssh und show ssh. Test vom PC: ssh -l admin 192.168.1.1.

Konsole und VTY absichern

Auch der physische Zugang über die Konsole braucht Schutz – sonst reicht ein Kabel. Dazu kommen sinnvolle Timeouts und verschlüsselte Passwörter.

enable secret cisco123                 ! privilegierten Modus schützen
service password-encryption            ! Klartext-Passwörter in der Config verschleiern
!
line console 0
 login local                           ! Benutzername/Passwort verlangen
 exec-timeout 5 0                      ! nach 5 min Inaktivität abmelden
 logging synchronous                   ! Logmeldungen zerhacken die Eingabe nicht
!
line vty 0 4
 transport input ssh
 login local
 exec-timeout 5 0
Nie exec-timeout 0 0 (Sitzung läuft nie ab) und nie transport input telnet oder all auf produktiven Geräten.

RADIUS: zentrale Anmeldung (AAA)

Lokale Benutzer auf jedem Gerät sind mühsam und unsicher (ausscheidende Mitarbeiter, Passwortwechsel). RADIUS zentralisiert die Authentifizierung, Autorisierung und Accounting: das Gerät (NAS) fragt einen RADIUS-Server, der alle Konten kennt.

aaa new-model
radius server RAD1
 address ipv4 10.1.1.10 auth-port 1812 acct-port 1813
 key Str0ngKey!
aaa authentication login default group radius local   ! erst RADIUS, dann lokal als Fallback
!
line vty 0 4
 login authentication default
Fallback nicht vergessen: das local am Ende sorgt dafür, dass du dich bei Ausfall des RADIUS-Servers noch lokal anmelden kannst. RADIUS verschlüsselt nur das Passwort; TACACS+ (Cisco) verschlüsselt die ganze Nachricht und trennt Authentifizierung und Autorisierung sauberer.
