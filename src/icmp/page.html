ICMP, ping und traceroute

ICMP ist das Melde- und Diagnoseprotokoll von IP: Es meldet Fehler und beantwortet Testpakete. Zwei Werkzeuge bauen darauf auf: ping prüft die Erreichbarkeit, traceroute deckt den Weg Hop für Hop auf.

Was ist ICMP?

ICMP (Internet Control Message Protocol, IP-Protokoll 1) transportiert keine Nutzdaten, sondern Status- und Fehlermeldungen. Die wichtigsten Typen:

MeldungWann
Echo Request / Replydie Grundlage von ping (Typ 8 / Typ 0)
Time Exceededdie TTL eines Pakets erreicht 0 – Router verwirft und meldet (Basis von traceroute)
Destination UnreachableZiel/Netz/Port nicht erreichbar (z. B. kein Weg, Port zu)
Redirect„nimm einen besseren Router" – Hinweis auf ein günstigeres Gateway

ping

ping schickt ein Echo Request und wartet auf das Echo Reply. Das zeigt: Ist das Ziel erreichbar, wie lange dauert es (Round-Trip-Time), gehen Pakete verloren?

C:\> ping 8.8.8.8
Antwort von 8.8.8.8: Bytes=32 Zeit=14ms TTL=117
Antwort von 8.8.8.8: Bytes=32 Zeit=13ms TTL=117
Statistik: Gesendet = 4, Empfangen = 4, Verloren = 0 (0% Verlust)

Keine Antwort heißt nicht immer „down": Manche Geräte/Firewalls blocken ICMP.

traceroute / tracert

traceroute macht sich die TTL zunutze. Jeder Router zieht beim Weiterleiten 1 von der TTL ab; wird sie 0, verwirft er das Paket und schickt ein Time Exceeded zurück – samt seiner eigenen Adresse.

Der Trick: Man schickt Pakete mit wachsender TTL. TTL 1 „stirbt" beim 1. Router (er verrät sich), TTL 2 beim 2., und so weiter – bis das Ziel selbst antwortet. So wird der ganze Pfad sichtbar.

Windows tracert nutzt ICMP Echo, Linux/macOS traceroute oft UDP – beide erkennen die Hops am Time Exceeded.
